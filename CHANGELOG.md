# Changelog

What changes from one TotalBase version to the next: what's new, and what an upgrade asks of you. Each version's section is also its [GitHub release](https://github.com/totalbase-io/totalbase/releases)'s notes (`scripts/release-notes.sh`). The step-by-step upgrade guide is in the [documentation](https://docs.totalbase.io/operations/upgrading).

## 0.1.0-beta.15 - 2026-11-23

### Highlights

- **Lockdown: the instance to yourself.** For an import, a restore, a change of schema: **Settings › General › Lockdown** (`lockdown.*`) makes TotalBase answer administrators only - their sessions and their ADMIN tokens - and everyone else `503 LOCKDOWN`, with your message: an administrator's API-plane token, incoming webhooks, embeds and MCP with any other token are refused too, and a user kept out waits on a page of their own, still signed in. Its switch turns it on, and **When** says when: **Now**, until you turn it off; **Scheduled once** (**From**, **Until**); or **Repeating** (a cron expression and a length: a maintenance hour every night or every week) - a scheduled one tells callers how long to wait (`Retry-After`, `meta.until`). **Mode** chooses between **Closed** and **Read-only**, where everyone signs in and reads as usual and only administrators and **Exceptions** change anything (`meta.mode` says which). **Exceptions** are roles whose users can also sign in and keep working, as themselves - a QA role, or the integration doing the work; **Pause workflows** keeps scheduled workflows from running and makes event-driven ones wait until it ends; **Tell users beforehand** shows everyone a notice some minutes before a scheduled one. Open sessions carry on afterwards, a forgotten password is still recovered, and health checks keep answering. A banner reminds whoever is inside, and `GET /api/instance` carries `lockdown` for your own application.
- **MFA has its own page, and can be required of the roles you choose.** **Settings › Access › MFA** (`mfa.*`) holds **Require MFA** - **No one**, **Everyone** or **Selected roles**, with the roles whose holders must use it (Administrators among them) - and the **MFA turned off notice**. A role's page shows **Requires MFA**, read-only, and a user's page whether it is required of them. Setting MFA up now lists authenticator apps to get one from. Status warns while the Administrators role isn't covered. **On upgrade:** `auth.mfa_required` and `auth.mfa_disabled_email_enabled` are gone and a value you stored for them is cleared - choose **Require MFA** again (**Administrators** is now **Selected roles** with the Administrators role).
- **Dashboard queries can run as a PostgreSQL role of your own.** **Settings › Features › Dashboards › Widget query role** (`dashboards.query_role`) names a role you create (`NOLOGIN`, `SELECT` on what dashboards read) and grant to TotalBase's role. Every widget query, totals, variable options and the editor's checks then read only what that role may, and nothing in the query can leave it: not `set_config('role', ...)`, and not SQL built from a variable's value. PostgreSQL enforces it, because the query runs inside a `SECURITY DEFINER` function the role owns (`totalbase.dashboards_query`, new in this version). Empty by default: queries run as TotalBase's role, as before. On PostgreSQL 16 and later, grant it plainly: a grant `WITH INHERIT FALSE` or `SET FALSE` is refused up front (`DASHBOARD_QUERY_ROLE_UNAVAILABLE`). Only a signed-in administrator can change it, never an API token, and Status warns when the role can't be used or can bypass Row Level Security or use the `totalbase` schema.
- **Private files are private: their uploader's alone. Linked files follow their record.** A file now has one of three visibilities, and it caps every permission on `files`: **Private** - whoever uploaded it, nobody else; **Linked** (new) - also whoever can read a record whose file column references it, by that record's own row filter, evaluated by PostgreSQL; **Public** - anyone with its address. Until now any App user with the default `READ` on files listed and opened every Private file of everyone. A form's **File upload**, **Camera** and **Signature** upload Linked, and so does a workflow's **Create file** (a new **Visibility** field). A list of files shows each caller only what they reach - a Public file too, since its unguessable id is what keeps it. The Files page's **Visibility** badge and bulk action offer the three. **On upgrade:** existing files keep their visibility, so a record's photo that was Private now shows to its uploader only - make it **Linked** in Files (bulk: select, **Visibility** › **Link to records**). An upload without `visibility` now takes **Public by default** (`files.default_visibility_public`) as documented, instead of always Private. One migration widens the column's check.
- **Only a file's uploader, or an administrator, sets its visibility - and you choose whether uploaders may make files Public.** Anyone else who reaches a file sees it but can't change who else does. A new setting, **Uploaders can make files public** (`files.uploader_can_publish`, on), turned off leaves Public to administrators alone - on upload, from **Create file** and afterwards. With **Audit reads** on for `totalbase.files`, opening a file's content or details is recorded in the audit log: who, which file, content or details, refused too. The Files list follows the system's table design: a **⋮** per row (Open, Download, Visibility, Move to folder…, Delete), a plain empty state, and **Visibility** as a button in the file's details instead of a clickable badge; **Modified by** stays in the details. A file's details are now a record form: **Name**, **Description**, **Tags** and **Visibility** saved together by **Save**, unsaved changes never dropped without asking, **Move to folder…** and **Delete** in its **⋮**, compact details with a copyable ID, and an image opens at full size. File sharing with chosen people and anonymous links are deliberately not planned.
- **Status tells you what the instance is, and what needs you.** The administrator's home opens with one line: the state (**Operational**, **Needs attention**, **Lockdown**, **Read-only**), the version, the environment, PostgreSQL, the uptime and the public URL. A **bell** in the header counts what needs attention, in the color of the worst item, errors first: failed executions, a failed backup, invalid indexes, connections from 80% of `max_connections` (an error from 95%), backups off, SMTP not configured, a generated master key file, a public URL that isn't the address you opened, a lockdown ahead. **Activity** charts the **Data API** and **Administration** by day over **Last 7 days**, **Last 14 days** or **Last 30 days**, a column's segment opening that day in **Logs**; a third card has **Space**, **Workflows** and **Backups**; then **System** (connections and pool meters, protection, queues) and **Services** (SMTP, Backups, S3, Audit, OpenAPI, GraphQL, Realtime, MCP, SQL Console - **On**, **Off** or **Not configured**). **Auto-refresh** sits beside **Refresh**.
- **Status checks how the instance is protected.** It warns about a public URL on `http://` that isn't this machine, rate limits or sign-in lockout off, a proxy forwarding requests TotalBase doesn't trust, unfiltered `UPDATE`/`DELETE` grants on the self-registration role, and, from PostgreSQL, a superuser connection role, `password_encryption` other than `scram-sha-256`, no TLS to a server outside a private network and privileges the connection role doesn't need (`CREATEROLE`, `BYPASSRLS`, `REPLICATION` while Realtime is off, the `pg_*_server_*` roles). Once an hour the server requests its own public URL through the reverse proxy: a refused or expired certificate is an error, one expiring within 14 days a warning, and security headers the proxy strips are named.
- **Latest configuration changes and latest sign-ins.** Two buttons in Status' header. **Latest configuration changes** lists by day what changed who may do what or how the instance is set up - a setting with its new value, a DataView, dashboard or workflow by name, schema changes too, a burst of the same change as one row. **Latest sign-ins** shows a row per person per day, with green, amber and red counts for signed in, denied and failed, opening into each attempt's door, browser, system and address; **Only refused** filters. A schema change is now the audit event `schema.apply`, and the log's **Target** names a settings change by its group, setting and new value.
- **A public webhook can ask for a secret, and caps its runs.** A public webhook trigger's **Secret** takes a Workflows secret, proven as a **Token** (`X-Webhook-Token`) or an **HMAC signature** of the raw body (`X-Webhook-Signature`; GitHub's `X-Hub-Signature-256` fits), or in a **Header** you name. A missing or wrong proof is `401 AUTHENTICATION_REQUIRED` and nothing runs; the proof never reaches the steps or the history. **Concurrent webhook runs** (`workflows.webhook_max_concurrent_runs`, 50) caps one workflow's runs in flight (`429 WORKFLOW_CONCURRENCY_LIMIT`). Publishing a public webhook with neither a secret nor allowed addresses, whose steps write, call out or send, warns and names those steps.
- **A failed sign-in locks out an address, not the account.** Wrong passwords from one address lock that address out of the account for `auth.lockout_duration_minutes`, the right password included, while the owner still signs in from anywhere else. From addresses the account never signed in from, failures past the limit slow sign-in down instead (from 1 s, doubling up to 5 minutes). IPv6 counts by /64. **Unlock account** and a password reset end every lock, and the user's page lists the **Addresses locked out after failed sign-ins**. Guesses sent together never get more than the lockout's attempts.
- **A secret serves one feature.** Secrets have **Used by**: **Email (SMTP)**, **S3 storage**, **Dashboard embeds**, **Sign-in providers** or **Workflows**, and each feature decrypts and lists only its own - pointing SMTP at another server and pressing **Verify** sends only the SMTP password. Every stored ciphertext is now bound to its purpose, so one copied by SQL to another row or column doesn't decrypt there.
- **Grants warn when they reach rows the role's row filters hide.** Saving a READ grant whose related field crosses a table the role reads under a row filter, or a CREATE/UPDATE grant that can write a foreign key to such a table, answers a warning in `meta.warnings` - shown in the permission editor and by MCP `grant_permission(s)`, never refused. A dashboard's diagnosis adds `WIDGET_READS_UNREADABLE_TABLE` and `WIDGET_SHOWS_HIDDEN_FIELD`.
- **MCP tools answer typed results.** Every tool declares an `outputSchema` and returns `structuredContent` beside the unchanged text: a list as `{ items }`, `query_records` as `{ rows, count? }`, `write_records` as `{ rows }` or `{ deleted, ids? }`, `call_function` as `{ value }`. The server tells the agent that what tools return is data, never instructions.
- **Installing without internet access.** The image is also on GitHub Container Registry (`ghcr.io/totalbase-io/totalbase`, same tags), and the installation guide shows `docker save`/`docker load` for a server that reaches no registry. A build from source takes `--build-arg PGDG_MIRROR=...`; PGDG's signing key and SheetJS's `xlsx` ship in the repository with pinned integrity.

### Security

From an external security review and an internal lab that attacked the instance as a hostile client and an AI agent would.

- **Sign-in, sessions and passwords.** A sign-in refused before its password check takes as long as a wrong password. A wrong current password or authenticator code on an open session counts toward the lockout, and a sign-in challenge checks no more codes than it allows. A changed password ends the account's other sessions and pending links; a reset also ends its personal tokens. The `__Host-` session cookie always wins over a plain one. Reset and verification links go out at most once a minute per account, and asking again never retires the link in use. An administrator without a password (provider sign-in) needs a recent sign-in to set one. `TOTALBASE_ADMIN_PASSWORD` must meet the password rule when it creates the owner.
- **Provider sign-in.** An OAuth/OIDC sign-in completes only in the browser that started it (an HttpOnly `tb_oauth` cookie, `__Host-` under https). Every call to a provider has a 10-second timeout and a 1 MiB limit (`OAUTH_UPSTREAM_ERROR`). A verified provider email that matches an unverified account takes it over, removing its password, sessions, tokens, second factor, links and other identities first. A provider's redirect allowlist takes only absolute http(s) URLs, and its default role can't be reserved or an administrator's.
- **Rate limits.** **Requests per minute per user** (`security.rate_limit_per_user_per_minute`, 1200) and **Failed sign-ins per minute** per address (`security.rate_limit_sign_in_per_minute`, 10) are always on; the switch, now **Limit per address**, governs the rest. Public routes count per address whatever credential they carry, each GraphQL operation and realtime subscribe over a WebSocket counts, and a process runs at most two password hashes at once (256 waiting, then `429`).
- **The master key and stored secrets.** The stored master-key verifier is no longer the encryption key: secrets, second factors, embed links and OAuth state are encrypted with keys derived from the master key per purpose. A second factor's secrets are protected columns. `files.storage_local_path` and `backups.local_path` must be directories inside the data directory, apart from each other; a backup never carries `master.key` or the setup code, a restore writes only inside the data directory, and local archives are `0600`. In the image the application files belong to root.
- **Files.** Opening a file shows it inline only for PNG, JPEG, GIF, WebP and PDF, recognized by content; anything else downloads, sandboxed. Uploads stop at `files.max_file_size_bytes` as they arrive, replaced content gets the same checks, and a file gets at most 64 new renditions an hour. An upload needs field grants for the columns it sets and must pass the CREATE row filter.
- **The Data API.** A collection `PATCH`/`DELETE` filter may name only fields the caller may read; a write answers only with what a read of the row would show. Protected and **Password** columns are never reached through a relation path, a self-reference or an OpenAPI relation, for anyone, and a Password column stays one through a rename. Unknown query parameters and unknown grant keys are refused by name. `search` takes at most 10 words, `_in`/`_nin` 10,000 values, `api.max_limit` 1-10,000, and `query.allow_regex`/`allow_contains` hold for `flags[...]` and delegated filters too.
- **GraphQL and realtime.** A GraphQL document costs its size, however its fragments expand, stops parsing at 10,000 tokens and selects at most `graphql.max_fields` fields (500). One user's realtime subscriptions are capped across connections (`realtime.max_subscriptions_per_user`, 200).
- **Delegated administration.** A manager's ownership of a role is judged before the write; a delegated grant's filters name only fields its parent may read; a delegated manager never removes or replaces an administrator's DENY; moving an assignment needs its old role to be assignable too. A token can't create or regenerate an `admin` token or write any token's `allowed_ips`.
- **SQL.** CHECK and DEFAULT expressions and data types can't add a clause to their statement (dollar-quoting refused, quotes balanced, multi-word types only as PostgreSQL spells them); SQL text is built from names and values that can't break it. Raw SQL - the SQL Console, an Execute SQL step, a widget's read-only transaction - leaves nothing on its pooled connection: role, settings, locks, temporary objects. A SETTINGS DataView reads its keys as the viewer.
- **Workflows.** A `{{…}}` in a filter is always a value, never the filter grammar. `_like`, `_ilike` and `_regex` are matched by PostgreSQL under a 1-second timeout. The **Execute SQL** step follows the SQL Console's switches. An HTTP step stops decompressing at its size limit and carries no secret header or body to another origin on a redirect. **Send email** takes at most 50 real addresses. A data event's rows reach a run only as PostgreSQL decides its executor may read them. A caller or viewer gets a failure's code, not its insides; the detail stays in the run's history, where credentials are redacted whatever their header is called. An authenticated webhook reads its credential from the `Authorization` header only.
- **Dashboards and embeds.** A published widget's cached result is always its viewer's own. An embed page shows only the embed its path names, never skips the cache, and needs an **Embedding secret** of 32 characters; a LOCKED variable can't be locked to nothing.
- **MCP Standard mode.** Standard mode removes and revokes nothing, through any tool: no turning a capability off, no DENY, no deactivating, ending a token or session, moving or expiring an assignment, narrowing an embed or an endpoint. Its `execute_sql` runs one statement read-only; it saves, runs or publishes no workflow that deletes records, runs raw SQL or revokes. In any mode `execute_sql` asks for `confirm` for everything that destroys as PostgreSQL reads it (`DO`, `CALL`, a deleting `MERGE`, ...). A tool's id stays one segment of its own route.
- **The admin.** Record text never becomes a script link, a spreadsheet formula or a framed SVG; file previews frame only allow-listed types; an Image widget reads only a file with the viewer's token; a code editor's link opens only a web address; the PDF designer fetches nothing a template points at. The admin's table preview never returns a protected or Password column. DOMPurify is past its known bypasses.
- **Headers and proxies.** Every answer carries `Permissions-Policy`, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy` (file content stays `cross-origin`). `security.trust_proxy` trusts the one proxy in front, not every hop. Guards decide on the route a request reaches, not its raw target. CORS origins, trusted proxies and provider redirects are checked when saved.
- **Audit.** A function call never audits a credential argument in clear, an audit entry never keeps a failed row's values, and an App user's audit event is held to its shape.

### Fixes

- **Role ids in settings are stored in lower case**, as PostgreSQL writes them (`mfa.required_roles`, `lockdown.allowed_roles`, `auth.registration_default_role`): an upper-case id used to match no role.
- **`REALTIME_UNAVAILABLE` names what's missing**: `wal_level` not `logical`, or TotalBase's role without `REPLICATION` (`meta.walLevel`, `meta.replication`).
- **Workflow publish catches what used to fail only on a run**: a Read records query that doesn't parse or names an unknown field, an Update/Delete records filter likewise, a `{{step...}}` reached only through that step's Error output.
- **`fields` as a list**: a repeated parameter or a JSON list in a Read records step is a plain list, not an alias map.
- **A grant's filter paths are checked when it is saved** (`400 INVALID_FIELD`, `INVALID_RELATION`), instead of breaking every later read of the roles holding it.
- **Data-event workflows whose executor's row filter uses a relation path or `$USER.*` run**, evaluated by PostgreSQL on the event's row; a transient match error is retried, not dropped.
- **A widget calling `pg_advisory_lock` no longer blocks TotalBase's own locks.**
- **`files.storage_local_path` and `backups.local_path` default inside the data directory** (`<data dir>/files`, `<data dir>/backups`).
- **The S3 settings page is called S3**, and a page whose whole body is empty says so two fifths down the page.
- **`pnpm dev` starts again** (running from source only).

### Before you upgrade

- **Six migrations apply on start**, on the `totalbase` schema only: a scope on `totalbase.secrets` (000025); `totalbase.users_addresses` and `users.sign_in_failures`, `users.sign_in_delayed_until` (000026, 000027); MFA's settings (000028); the function `totalbase.dashboards_query` (000029); `files.visibility` accepts `LINKED` (000030).
- **Stored secrets are re-encrypted once on the first start**, and the server writes a `ciphertext-format` file in the data directory. Take a backup first - a beta.14 server can't read what this one writes - and keep the same master key. Backups made before this version hold the old verifier, from which their secrets can be decrypted: keep them as safe as the key, or rotate those secrets. They still restore with `totalbase restore`. Keep the data directory on persistent storage; a database put back on the old format by other means fails to start with `INVALID_MASTER_KEY` until that file is removed.
- **Each secret now belongs to one feature.** The migration gives a secret the first feature that uses it (providers, SMTP, S3, embeds, else Workflows): a secret shared between features keeps one, so check **Settings › Security › Secrets › Used by** and give the other its own. `PUT /admin/api/secrets/{key}` requires `scope`.
- **Storage paths must be inside the data directory.** An override of `files.storage_local_path` or `backups.local_path` outside `TOTALBASE_DATA_DIR` makes saves and backups fail with `INVALID_SETTING`: move the directories. With a custom `TOTALBASE_DATA_DIR` and no override, files now default to `<data dir>/files` - move them there from `/var/lib/totalbase/files`, or set the old path, before starting. The image's `/app` is read-only for the server.
- **Rate limits are on.** 1200 requests a minute per user, shared by all their sessions and tokens - raise `security.rate_limit_per_user_per_minute` for a heavy integration, or set 0 - and 10 failed sign-ins a minute per address. Behind a reverse proxy, set **Trust reverse proxy headers** (one hop now) and list a chain of proxies in **Trusted proxies**, or every caller shares one address.
- **Lockout is per address.** A tool that read `users.locked_until` alone misses address locks: use **Unlock account**.
- **Requests that used to pass are refused.** Unknown Data API query parameters (`400 INVALID_QUERY`, e.g. `sort` for `order_by`, a cache buster `_=`); unknown keys in a grant body; a collection `PATCH`/`DELETE` filtering on a column the caller can't read (`403 FIELD_PERMISSION_DENIED`); the new caps (`search` 10 words, `_in` 10,000 values, GraphQL 10,000 tokens and 500 fields, 200 realtime subscriptions per user, 50 concurrent webhook runs); an upsert with `DO UPDATE` on a table that doesn't expose `PATCH`; an authenticated webhook called with a session cookie instead of `Authorization`. MCP `grant_permission(s)` keeps an existing row filter when `where` is omitted (`where: null` clears it).
- **Workflows to re-check and republish.** `_regex` is POSIX (`\y` for a word boundary, `.` matches a line break); a filter value from `{{…}}` is a value, so `"a,b"` is no longer split by `_in` - pass a list; a whole filter from a binding can't be published; **Execute SQL** fails while `sql_console.enabled` is off; **Send email** sends to at most 50 addresses; an HTTP step refuses a cross-origin 307/308 with a body. A caller now gets a failure's code and a generic message unless the author wrote it (**Finish with error**, **Validate data**).
- **Tokens and passwords.** A token can't create an `admin` token or write `allowed_ips` - do it from a session. A password reset revokes the account's personal tokens; a password change ends its other sessions.
- **Embeds.** An **Embedding secret** under 32 characters checks no token: set a longer one and re-sign. A LOCKED variable needs a real value; `"fresh": true` is ignored.
- **Files.** Opening anything but PNG, JPEG, GIF, WebP or PDF downloads it. An upload that sets `visibility`, `folder`, `description` or `tags` needs the field grant.
- **MCP Standard mode does less**: a view, function or trigger through `execute_sql` needs **Full**.
- **`GET /admin/api/dashboard` changed shape** (Status): `activity.data`, `activity.admin` and `activity.problems`; a `days` window of 7, 14 or 30 (30 by default); new `instance`, `services` and severities.
- **Sign-ins in progress at upgrade time may fail once** (the new OAuth browser binding).

## 0.1.0-beta.14 - 2026-11-16

### Highlights

- **Node.js 26.** TotalBase runs on Node.js 26, the Active LTS line since October 2026 (supported until April 2029) and the one the workflow JavaScript sandbox (`isolated-vm` 7) is built for. The image moves to it on its own.
- **Current dependencies.** Fastify, `pg`, Nuxt 4.6 and Nuxt UI 4.12, Vue, the rich-text editor (tiptap 3.33), pdfme 6.2, `pino` 10, `jose` 6, `fast-xml-parser` 5, `argon2` 0.45, gridstack 14 and the Monaco editor 0.57, among the rest. Nothing to change on your side: a password stored before still signs in, a SOAP step reads its answers the same way, dashboards lay out as before.
- **A forged sign-in token is a 401.** An OIDC or Google `id_token` that fails verification - signed by another key, for another client or issuer, expired - now answers `401 INVALID_OAUTH_STATE`, like one from another sign-in attempt, instead of `500 INTERNAL_ERROR`; a key set the provider can't serve is `502 OAUTH_UPSTREAM_ERROR`. It was always refused; now it says so.
- **An edited image shows itself at once.** A file's content - the original or a resized rendition - is now revalidated against its checksum (`ETag`, `no-cache`, a `304` while unchanged): after **Save and replace** or a replaced image, previews and thumbnails show the new content, not a copy the browser kept for 30 days. `files.transforms.cache_ttl_seconds` now sets only how long the stored rendition is kept.
- **Save closes a file's properties**, as a record form's does.
- **"Nothing to publish" everywhere.** Publishing a DataView or a dashboard whose draft already equals the live version now says so, as a workflow's did, instead of announcing a version that was already there - and an agent's publish tool says `published: false`, so it notices edits that never reached the draft.
- **One table editor: the table's page.** A column's panel has a **Database** tab (name, type, nulls, default, uniqueness, foreign key) beside its presentation, with the `ALTER` statements shown as you edit. One **Save** runs them and then saves the presentation, in one transaction: if PostgreSQL refuses the change, nothing is saved. **Primary key** and **Rename** show their SQL the same way. The Tables list's **Edit** opens the page; the old Edit table drawer is gone, and a table can now be renamed without the SQL Console.

- **My account for an application's own users.** Everything a person does on their own account - their sessions, two-factor authentication, email, password, picture, preferences - is now at `/api/auth/account/*` for any signed-in user, including one with API access only who never opens the App. The same operations and safeguards as the admin's My account, documented in OpenAPI.

- **The system emails' footer is yours.** Every system email ended with the instance's name and its address; **Settings › General › SMTP › Footer** (`mail.footer`) now says what that line is, or leaves it out - for an application whose users never see TotalBase's own address.

- **An invitation can say who invites, as what, and a line of your own.** The Invitation email's template takes `{{inviter.name}}`, `{{inviter.email}}`, `{{roles}}` and `{{message}}` - the last a `message` the caller adds in `POST /api/totalbase/table/users/invitations`, `.../users/{id}/invite` or `POST /admin/api/users/{id}/invite`. The built-in text is unchanged.

- **A secret column can stay out of events too.** A column excluded from a table's audit log can also be excluded from the event webhooks and workflows receive (the table's **Auditing** section, or `eventExcludedFields` in `PUT /admin/api/resources/{id}/audit`). And an audit entry now says that an excluded column changed, without its values.

- **A maximum password age, and a new password on request.** For a deployment whose policy asks for it: **Settings › Access › Maximum password age** (`auth.password_max_age_days`, off by default - current guidance advises against periodic changes). Someone whose password is older signs in as usual and chooses a new one right there, after their two-factor code, before getting in; nobody is locked out and no email is needed. An administrator can ask one person for the same, whatever the setting: **Require a password change** in a user's ⋮ menu, or **Ask for a new password at their next sign-in** when setting a temporary one (`mustChange` on `PUT /admin/api/users/{id}/password`). For your own sign-in page: a correct sign-in answers `403 PASSWORD_CHANGE_REQUIRED` with a challenge, finished with `POST /api/auth/password/renew`. And a password change - by its owner, anywhere - no longer accepts the password the account already has (`400 PASSWORD_UNCHANGED`). Sessions already open, API tokens and provider sign-ins are not affected; the age of the passwords you already have counts from this upgrade.
- **Remove a user without deleting them.** For someone who is no longer part of the organization: **Remove user** (a user's Danger zone, `POST /admin/api/users/{id}/remove`, or `POST /api/totalbase/table/users/{id}/remove` for a role with `UPDATE` on users, inside its row filter) keeps the account - the audit log goes on naming them - and takes away every way in: password, sessions, API tokens, two-factor authentication, sign-in providers, pending links and roles. Users lists them as **Removed**; an invitation brings them back.
- **A token, and a webhook, can be limited to the addresses that call them.** **Allowed IP addresses** on a personal access token (`allowedIps` when it is issued, the `allowed_ips` column after; **Allowed IP addresses…** in a token's ⋮ menu) takes addresses and ranges: from anywhere else the token answers `403 TOKEN_IP_NOT_ALLOWED`, on every API. A workflow's **Webhook** trigger has the same list, for public webhooks too: from anywhere else it answers `404`, as if it didn't exist. Both are empty by default - nothing changes until you fill one - and behind a reverse proxy they need the proxy in **Trusted proxies**. One migration adds the column.
- **A refused token is in the audit log.** A personal access token that is presented and refused - revoked, deactivated, expired, its user deactivated, or used from outside its allowed addresses - leaves a *Denied* entry, `auth.token_refused`, with the reason, the address and the route (at most one a minute per token and reason; a secret that is no token's is not logged). **Status** counts the last 24 hours' under what needs attention, and Logs has a **Refused tokens** security view.
- **An HTML body escapes what it is given.** In a **Send email** step's HTML body, a `{{…}}` is now replaced by its value as text - `<`, `>`, `&` and quotes escaped - as a template's message always did: text typed into a public form can no longer arrive as markup. A body that is one `{{…}}` in full is still sent as that value, for HTML another step builds. **If a workflow of yours spliced HTML into a written body** (`<div>{{step.data.html}}</div>`), it now arrives as text: make the body that one expression.
- **Send email can retry.** A workflow's **Send email** step takes **Retries** (0 to 5, off by default): it sends again, after 5 s to 2 min, when the mail server is unreachable or answers with a temporary `4xx` error - never when the message may already have gone, so a retry can't be a second copy. The step's result says how many attempts it took.
- **An invitation, a reset or a removal sent through the Data API says who sent it.** The audit entries of `POST /api/totalbase/table/users/...` (`user.invite`, `user.password_reset`, `user.remove`) recorded no principal.

### Fixes

- **A list into a `json`/`jsonb` column.** `POST` and `PATCH` on a table (single, upsert, nested, in a transaction) now store a list - of objects, of scalars, empty - as JSON. It reached PostgreSQL as an array literal before, refused with *invalid input syntax for type json*; beta.13 fixed the same for function arguments.
- **A read by key takes `fields`.** `GET /api/{schema}/table/{table}/{pk}?fields=id,customer.name` returns those fields, relation paths and aliases included, as the list read does; the parameter was ignored. The READ audit entry records them, and OpenAPI documents the parameter.
- **An empty body with `Content-Type: application/json` is no body.** A `DELETE` or a body-less `POST` from an HTTP client that sends the header on every request answered `400`; it now answers as without the header. A sign-in, password or token route called with no body at all answers its own 4xx instead of a `500`.
- **`count=true` no longer joins the relations you only read.** The total keeps the joins `where`, `search` and the row filter use and drops the ones that come from `fields` and `order_by`, which never change the number of rows - a count over a large table no longer pays for the related names its rows show.
- **System emails are centered.** Their frame (520 px wide) sat against the left edge in a wide mail client.
- **Deleting a user records who it was.** The `user.delete` audit entry keeps the deleted account's email and name beside its id, which no longer resolves to a row.
- **OpenAPI types `bigint` and `numeric` as strings** (`int64`, `decimal`) - what the Data API returns them as. A client generated from the document no longer rejects real responses.
- **View as reads files as the previewed role or user.** Images, signatures, camera shots and file cells in a previewed App were fetched with the administrator's grants.
- **Add Column with a validation works on any column name.** A CHECK made from a column input now quotes the column, so an upper-case name or a reserved word no longer fails; its numbers must be numbers.
- **A PUT that replaces a set refuses a body without it** - a role's managers or incompatible roles, a column's presentation - instead of clearing it.
- **An id in the path that isn't one is a `404 ROW_NOT_FOUND`**, not PostgreSQL's `400` for a malformed uuid.
- **Copy works on an instance served over plain HTTP.**
- **The Resources browser refreshes the sidebar** after dropping resources or changing their endpoints, and Save endpoints no longer waits 1.5 s.
- **Errors read in the UI's language** in View as, the file editor, an image's preview and a query's records.
- **Applying a dashboard spec judges a taken name as creating one does** - case-sensitive, like its UNIQUE constraint.
- **Settings that showed their key** (Registration columns, Requests per minute per user, Trusted proxies, Excluded schemas) have their label and help.
- **A page size out of bounds is a `400 INVALID_QUERY`** on a table's row preview (`GET /admin/api/catalog/table/{id}/rows`, 1-200) and SQL Console history (1-500), as on the other lists; a value that wasn't a number reached SQL before.
- **Every administrator's audit entry records where it came from** - IP, user agent and the admin-plane token, if any - including View as, embed changes, stopping a maintenance batch and applying a dashboard spec.

## 0.1.0-beta.6 - 2026-10-25

### Highlights
